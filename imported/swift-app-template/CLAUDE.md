# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repo Is

This is a **GitHub template repository** being built to provide reusable Swift app infrastructure (Tuist, Fastlane, CI, linting, Swift Testing, Claude Code integration) for any Apple platform app.

## Placeholder Convention

All app-specific values use `{{TEMPLATE_*}}` tokens that `Scripts/setup.sh` replaces interactively:

| Token | Example value |
|---|---|
| `{{TEMPLATE_APP_NAME}}` | `WeatherBar` |
| `{{TEMPLATE_TEAM_ID}}` | `ABCDE12345` |
| `{{TEMPLATE_APPLE_ID}}` | `dev@example.com` |
| `{{TEMPLATE_ITC_TEAM_ID}}` | `1234567` |
| `{{TEMPLATE_ORG_NAME}}` | `Acme Corp` |
| `{{TEMPLATE_GITHUB_ORG}}` | `myorg` |
| `{{TEMPLATE_CERTS_REPO}}` | `git@github.com:myorg/AppCerts.git` |
| `{{TEMPLATE_APP_GROUP_ID}}` | `group.com.example.WeatherBar` |
| `{{TEMPLATE_PACKAGE_NAME}}` | `WeatherBarKit` |
| `{{TEMPLATE_YEAR}}` | `2026` |
| `{{TEMPLATE_SERVER_PORT}}` | `8080` *(full-stack only — Dockerfile, openapi.yaml, server Swift source)* |
| `{{TEMPLATE_MARKETING_URL}}` | `https://example.com/` |
| `{{TEMPLATE_PRIVACY_URL}}` | `https://example.com/privacy-policy.html` |
| `{{TEMPLATE_SUPPORT_URL}}` | `https://example.com/support` |
| `{{TEMPLATE_FASTLANE_PLATFORM}}` | `mac` *(fastlane platform identifier — `mac`, `ios`, `tvos`, `watchos`)* |
| `{{TEMPLATE_PRODUCE_PLATFORM}}` | `osx` *(`produce` action platform string — `osx`, `ios`, `tvos`, `watchos`)* |
| `{{TEMPLATE_TEST_DESTINATION}}` | `platform=macOS` *(xcodebuild destination string)* |
| `{{TEMPLATE_BUILD_ARTIFACT_EXT}}` | `pkg` *(`pkg` for macOS, `ipa` for iOS/tvOS/watchOS)* |
| `{{TEMPLATE_DESTINATIONS}}` | `[.iPhone, .iPad]` *(Tuist destinations array — e.g., `[.mac]`, `[.iPhone, .iPad]`)* |
| `{{TEMPLATE_DEPLOYMENT_TARGET}}` | `.iOS("26.0")` *(Tuist deploymentTargets — e.g., `.macOS("26.0")`, `.iOS("26.0")`)* |

`{{TEMPLATE_BUNDLE_ID}}` is auto-derived by `setup.sh` as `com.<org_slug>.<APP_NAME>` (org name lowercased, punctuation removed).

`CLAUDE.md` and `README.md` are meta docs for the template repo itself — they never contain `{{TEMPLATE_*}}` tokens. `CLAUDE.template.md` and `README.template.md` contain placeholders and become the generated project's docs when `setup.sh` renames them.

## Template Architecture

After `setup.sh` runs on a generated project, the structure is:

```
Packages/
├── {{TEMPLATE_APP_NAME}}Kit/     ← cross-platform business logic (SPM package)
│   ├── Sources/{{TEMPLATE_APP_NAME}}Kit/
│   │   ├── AppModel.swift        ← @Observable AppModel with actor pattern
│   │   └── UserDefaults.swift
│   └── Tests/{{TEMPLATE_APP_NAME}}KitTests/
│       ├── AppModelTests.swift
│       └── TestHelpers/Platform.swift
├── {{TEMPLATE_APP_NAME}}App/     ← SwiftUI app (depends on Kit) (SPM package)
│   └── Sources/{{TEMPLATE_APP_NAME}}App/
│       ├── {{TEMPLATE_APP_NAME}}App.swift   ← @main entry point
│       └── Views/
├── {{TEMPLATE_APP_NAME}}Server/  ← optional Hummingbird server (full-stack only, kept/removed by setup.sh)
│   └── Sources/
│       ├── {{TEMPLATE_APP_NAME}}Server/     ← AsyncParsableCommand + Hummingbird router
│       └── {{TEMPLATE_APP_NAME}}serverd/    ← executable entry point
└── TemplateGenerator/            ← dev-only Swift executable (removed by setup.sh)
Project.swift                     ← Tuist manifest (all values → placeholders)
Scripts/setup.sh                  ← interactive placeholder replacement
Scripts/lint.sh                   ← SwiftLint + swift-format runner
fastlane/                         ← certificate management + TestFlight deployment
.github/workflows/app.yml         ← cross-platform CI (Linux, Windows, Android, Apple)
```

The Xcode project (`.xcodeproj`) is generated by Tuist and is not committed.

### Key architectural decisions (from MonthBar reference)

- **Tuist** manages Xcode project generation (`Project.swift`). Never edit `.xcodeproj` directly.
- **Two packages**: `*Kit` (pure Swift, cross-platform) and `*App` (SwiftUI, Apple platforms). Tests live in `*Kit`.
- **Swift 6.3** language mode with `SWIFT_STRICT_CONCURRENCY = complete`; Linux/Windows/Android CI and the dev container use the Swift 6.4 release.
- **Beta/release numbering** — `Config/Version.xcconfig` (written only by `Scripts/update-version.sh`); a `BETA_BASE_BUILD` line marks a beta.
- **Staged files** — `.github/*.workflow.yml` (moved into `workflows/` by `setup.sh` so they don't run here), `.claude.template/` (promoted to `.claude/`), `CHANGELOG.template.md`.
- **Manual code signing** via Fastlane Match — certificates stored in a separate private repo.
- **`mise`** manages tool versions (tuist, swiftlint, swift-format, ruby, etc.).

## Commands (once template is built)

```bash
# Generate Xcode project (auto-fix linting mode)
make generate
# or: mise exec -- tuist generate

# Generate with strict linting (matches CI)
make generate-strict
# or: TUIST_LINT_MODE=STRICT mise exec -- tuist generate

# Run linting (auto-fix in dev, strict in CI)
make lint
# or: ./Scripts/lint.sh
# CI strict mode: CI=true LINT_MODE=STRICT ./Scripts/lint.sh

# Test the Kit package (primary test target)
swift test --package-path Packages/{{TEMPLATE_APP_NAME}}Kit

# Certificate management
make certs          # sync all certificates
make certs-dev      # development certificates only

# TestFlight deployment
make beta           # build and upload to TestFlight
```

## Swift Testing Conventions

All test code uses **Swift Testing only** (no XCTest).

### Suite structure

- **< 10 tests**: single `@Suite struct` in one file
- **≥ 10 tests or multiple categories**: parent `enum` + per-category extension files

```swift
// AppModelTests.swift — parent enum carries "Tests" suffix; child structs do not
@Suite("App Model")
internal enum AppModelTests {}

// AppModelTests+Initialization.swift
extension AppModelTests {
  @Suite("Initialization")
  internal struct Initialization { ... }
}
```

File name mirrors the types: `AppModelTests+Initialization.swift`, never `AppModelTests+InitializationTests.swift`.

### Test data and assertions

```swift
private static let initialCount = 0

@Test("Initial count is zero")
internal func initialCount() {
  #expect(Self.initialCount == 0)  // always private static let, accessed via Self.
}
```

Use `#expect()` and `try #require()`. Never `XCTAssert*`.

### Platform-conditional tests

`TestHelpers/Platform.swift` provides a `Platform` enum. Apply via `.enabled(if: Platform.isMacOS)` on `@Suite` or `@Test` — prefer suite-level so the condition is declared once.

### MARK order in test files

```swift
// MARK: - Test Data Setup
// MARK: - Initialization Tests
// MARK: - Functional Tests
// MARK: - Error Handling Tests
// MARK: - Edge Cases
```

## SwiftUI Patterns

Platform-specific view logic goes in a `private extension` of the view itself — not in a global `View` extension:

```swift
internal struct MyView: View {
  internal var body: some View {
    VStack(alignment: alignment) { ... }
  }
}

private extension MyView {
  var alignment: HorizontalAlignment {
    #if os(watchOS) .leading #else .center #endif
  }

  @ViewBuilder var iconView: some View { ... }
}
```

Properties first, then `init`, then methods.

## CI/CD Overview

`.github/app.workflow.yml` → `.github/workflows/app.yml` (templated from MonthBar's `monthbar.yml`, hardened from AtLeast) runs:
1. `build-ubuntu` — Linux (Swift 6.4), including WASM variants
2. `build-windows` / `build-android` — Swift 6.4, cross-platform PRs only
3. `build-macos` / `build-macos-platforms` — SPM + Apple simulators
4. `lint` — SwiftLint + swift-format strict mode
5. `fastlane` — release build; on main, TestFlight upload + build-number commit; `production_release` dispatch input for production builds

Also staged: `app-store-metadata.workflow.yml` (manual listing sync) and `asc-session.workflow.yml` (weekly `FASTLANE_SESSION` check). `cleanup-caches.yml` / `cleanup-pr-caches.yml` run in both the template and generated repos.

`.github/workflows/validate-template.yml` (template-repo-only CI) greps for `{{TEMPLATE_APP_NAME}}` to confirm placeholders haven't been accidentally replaced.

Claude Code GitHub integration: `claude.yml` triggers on `@claude` mentions in issues/PRs; `claude-code-review.yml` reviews all PRs automatically.

## TemplateGenerator (dev-only)

`Packages/TemplateGenerator/` is a Swift executable depending on SyntaxKit that generates skeleton Swift files for any app name. `setup.sh` calls it to produce syntactically valid output, then removes the package. It is never shipped to end users.
